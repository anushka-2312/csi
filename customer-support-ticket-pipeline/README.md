# Customer Support Ticket Resolution Pipeline

A Bronze → Silver → Gold data pipeline that turns two days of raw customer-support
ticket exports into a clean, query-ready dataset answering four leadership questions.

## Problem

Support agents log every ticket they close to a CSV, uploaded daily to cloud storage
(ADLS Gen2). The raw files can't be queried directly: resolution times are stored as
text (`"1h 10m 20s"`), there's no link between a ticket and the agent's team, some
tickets are unresolved or invalid, and some agents fall outside the review's scope.

This pipeline ingests, validates, transforms, filters, and aggregates that data to answer:

1. **Ticket resolution rates across the Team Lead hierarchy** (TL01-TL08)
2. **Per-agent performance** for Day 1 vs Day 2
3. **Compliance with the >15-minute quality threshold**
4. **Which agents carried over unresolved work** from Day 1 into Day 2

Full rule definitions are in [`docs/business_rules.md`](docs/business_rules.md).

## Project structure

```
customer-support-ticket-pipeline/
├── README.md
├── requirements.txt
├── data/
│   ├── raw/                        # source CSVs (agent_profiles, day1/day2 tickets)
│   └── gold/                       # pipeline output — the 4 KPI tables
├── src/
│   ├── generate_sample_data.py     # builds the synthetic raw CSVs
│   └── pipeline.py                 # runnable Bronze/Silver/Gold implementation (pandas)
├── notebooks/
│   └── customer_support_pipeline.py  # Databricks-ready PySpark notebook (same logic)
└── docs/
    └── business_rules.md
```

Two implementations are included on purpose:

- **`src/pipeline.py`** — pandas, runs anywhere with `python3`, no cluster needed.
  Useful for quickly checking the logic and outputs (that's how the numbers in this
  README were produced).
- **`notebooks/customer_support_pipeline.py`** — the Databricks-source-format
  notebook, using PySpark's DataFrame API against ADLS Gen2 / Unity Catalog. Import
  this directly into a Databricks workspace to run it on a real cluster.

Both implement the identical rules, so results match.

## Running locally

```bash
pip install -r requirements.txt
python3 src/generate_sample_data.py   # (re)builds data/raw/*.csv
python3 src/pipeline.py               # runs Bronze -> Silver -> Gold, writes data/gold/*.csv
```

## Running on Databricks

1. Upload the three files in `data/raw/` to an ADLS Gen2 container (or DBFS/Volumes for testing).
2. Import `notebooks/customer_support_pipeline.py` into your Databricks workspace
   (File → Import → this file is already in Databricks source format).
3. Set the `adls_base_path`, `catalog`, and `schema` widgets at the top of the notebook.
4. Run all cells. Bronze/Silver/Gold tables are written to `{catalog}.{schema}` in Unity Catalog.

## Notes on the sample data

`data/raw/*.csv` is synthetic data generated by `src/generate_sample_data.py`
(seeded, so it's reproducible) — it's built to exercise every rule in the spec:
null/blank fields, unresolved tickets, out-of-scope team leads, resolution times
that straddle the 15-minute threshold, and agents who succeed on Day 1 and also
appear on Day 2 (to trigger the carry-over exclusion). Swap in the real
`day1_tickets.csv` / `day2_tickets.csv` / `agent_profiles.csv` exports and the
pipeline works unchanged, since the schema is identical.
